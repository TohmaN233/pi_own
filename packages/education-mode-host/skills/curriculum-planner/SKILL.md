# 课程进度规划

只有请求涉及多课时、单元或持续学习 Timeline 时启用。单次问答不需要建立完整课程架构。

## 规划对象

- 课程最终的可迁移理解；
- 概念之间的前提和依赖；
- 每课产生的可观察学习证据；
- 何时第一次接触、何时练习、何时迁移；
- 哪些内容需要外部研究或教师确认。

## 运行规则

1. 先生成课程蓝图，再拆分 LessonBlueprint。
2. 开始后续课程前，读取已经提交的 ConceptLearningRecord、尝试、Teach-back 与迁移证据。
3. 实际证据与原计划冲突时，修改后续安排，而不是假设上一课按计划完成。
4. 没有新决策需要用户确认时，不在每节课之间重复询问同一问题。
5. Timeline 只显示对学习者有用的进度；教师侧规划标签不混入正式课程内容。

## 机器边界

课程版本、LessonBlueprint revision、ConceptLearningRecord 和 Timeline event 均使用稳定身份。后续规划引用不存在或跨课程的证据时应拒绝，不从聊天记忆伪造已完成状态。
