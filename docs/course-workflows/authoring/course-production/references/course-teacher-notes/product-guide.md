# Teacher lecture scripts (TeX)

A teacher lecture note is an independent, teachable exposition, not a slide-by-slide paraphrase, a timed list of commands, the lesson blueprint, or speaker-note toggles. It can accompany a new deck or be generated later for any existing Beamer, including an accepted deck. Read the actual current deck, the compiled page count, the approved lesson, relevant source excerpts and the session duration first; preserve the deck unchanged when the request concerns only notes. Match the course language and teacher preferences. Use the deck's frame order as a navigation spine. Every section heading states the compiled PDF page numbers it covers, for example "PDF pages 3--4", and those numbers are updated after the final compile. A note without page references is not usable in class. Write the explanations the slides omit, including why a first example is hard to invert, but do not hide a density that students need to see: if it belongs on the slide, it must be written there and then interpreted in the notes. For each major concept give its motivation and prerequisites, define notation and assumptions, develop the mechanism/derivation step by step, interpret each step, work a numerical or code trace, distinguish exact mathematical claims from empirical/computational checks, explain a boundary or failure case, and connect it to the next concept. Cite sources versus teacher-derived examples without inventing source support. If a visual is on a frame, describe what its axes/geometry encode and the conclusion it supports, not merely 'point at the figure'. For R, explain what each consequential expression computes, what must be validated, and what a wrong result would mean; do not simply copy slide code.

Plan for the actual session length before drafting: allocate a realistic number of minutes across conceptual blocks whose total equals the session duration (include a modest allowance for independent calculations or actual execution), and ensure each block contains enough *explainable material* to occupy its allotted time at a normal lecture pace. A timestamp does not create coverage. For a 50-minute class, an 18-frame one-sentence-per-frame script or four-page list of slide cues is not sufficient; length is a diagnostic, not a fixed page-count quota. Expand thin blocks with genuinely new reasoning, a second worked input, a contrast or a limit, not padding. Audit after drafting: read through the note without the slides and ask whether the exposition itself supports teaching each block and the full session; if not, deepen it before compiling.

Do **not** script hypothetical dialogue, expected student replies, invented misconceptions voiced by students, or minute-by-minute stage directions. Real interaction cannot be predicted. Where the approved lesson calls for a check, include only the concise task, correct solution and diagnostic reasoning for the teacher to use flexibly; allocate time for independent work without pretending it happened. Prefer coherent paragraphs, displayed derivations and compact tables over repeated 'Say:', 'Ask:', 'Expected:' and 'Transition:' lines. Keep board-work suggestions only when they make the reasoning clearer. The note must remain useful to teach from if the projected deck is unavailable.

Use a standalone `article`, `report`, `book` or corresponding `ctex` document, with suitable math packages and complete document boundaries.
The scoped Host commits the new standalone TeX as a new teacher-note draft, binds the exact current deck and retains teacher review. Return a newly chosen source path; IDs, source hashes and revisions are not author output. Host compiles the exact saved source. Ordinary source failures retain diagnostics for scoped repair; an existing successful PDF stays available.
