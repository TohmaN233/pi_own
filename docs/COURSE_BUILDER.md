# Course Builder：备课与 Beamer

## 同页备课与模式设置（2026-09-05）

教师工作台在同一页显示课程操作和原 Pi Agent 对话。进入已有工作区时，在原会话上激活备课模式并保留 JSONL 历史；不会仅因打开页面就发送模型请求。Agent 启动失败时，对话区显示错误和重试按钮，已保存的课程仍可编辑。

右侧的 **Skills 与提示词** 展示项目根目录 `skills/`（可由 `PI_SKILLS_DIR` 指定）、模式组合、完整技能原文与实际加载状态。必需技能受合同约束；可选技能和系统提示词可以修改并应用，保存为当前会话的一份新快照。切换模式时自动换入对应提示词与组合，切回时恢复自己的修改。模型和推理等级也通过同一事务修改，保留原会话和历史。

Pi Web 使用 SDK 0.85.1，包含 `openai-codex/gpt-6-astra`。Codex 订阅模型目录随 SDK 发布，浏览器刷新不会自行升级 SDK；账号权限与 `enabledModels` 设置仍决定可用列表。

本功能通过普通 Pi 会话的 `course-builder` Mode Pack 加载专用插件、物理教学 Skills 及固定工作流，
复用 Pi 原生对话与 LearningHarness 的 SQLite 连接。不是第二套 Agent Loop。

## 开始

备课栏顶部的“模块跳转”固定显示课程概览、课程资料、Assignment、Agent 备课、学期计划、单课教案、覆盖进度、课件与验收和教学可视化。滚动时标出当前模块；窄屏目录可以横向滚动。跳转链接可直接打开或刷新，并在课程加载后定位，右侧对话保持独立滚动。

“接受当前有据版本”旁会说明未满足的条件。当前版本必须编译成功，并针对这次编译执行“检查源码和日志”；检查失败时直接列出问题。检查通过后，打开当前 PDF 逐页检查并勾选确认，即可接受。新源码版本或新的编译回执需要重新检查，旧版检查和人工确认不能沿用。系统不会代替教师验收。

课程可以包含多条对话。备课 Agent 上方显示课程内的对话列表，选择即可切换，点击“新建对话”并填写名称即可创建空对话。课程资料、学期计划、单课教案、Assignment 与课件属于课程，在这些对话间共享；各条聊天记录互相独立。项目默认模型、提示词和 Skills 会在新建时继承，单条对话可以单独调整。展开“项目默认设置”，可将当前对话的设置保存为以后新对话的默认值。

主页顶部“项目与对话”打开 `/projects`：课程和普通任务都按文件夹展示，可新建普通项目和项目内对话。普通对话可整理到项目中或移回项目外。顶部“新建独立对话”和原 Pi 的新建入口继续创建独立聊天，不继承当前课程。已有课程与对话会直接出现在目录中，无需重建。

课件区域点击“编辑 .tex”可在侧栏修改源码和 Frame 大纲，保存会生成新的未验收草稿，再点击“编译已保存源码”。未保存修改在本机暂存，重新打开可恢复；旧编辑不会覆盖其他对话刚保存的新版本。PDF 默认在浏览器内预览，下载按钮单独保留。课程计划审阅提示只在第一次生成学期计划时显示一次，刷新、修改版本或生成单课不会再次自动弹出。

单课计划可点击 **打开教案 · 阅读、编辑与审批** 在独立 HTML 页面查看。页面排版展示目标、前置知识、误解、逐段教学活动、练习、可视化与资料，支持公式和 Markdown。点击“编辑教案”可直接修改，保存为新草稿后再批准；这些操作不启动模型。未保存编辑与审阅意见按会话和教案在本机暂存，重新打开可恢复；工作区已有新版本时拒绝覆盖。返回按钮回到原课程。

添加技能：打开 **Skills 与提示词 → 技能库 · 添加与市场 → 添加技能**，搜索 skills.sh 市场或填入仓库地址/技能标识。普通 Pi 的“技能”设置页也提供相同入口。新增技能及后续更新统一保存到项目 `skills/`（默认 `<project>/skills`；可由 `PI_SKILLS_DIR` 配置），保留正文、参考资料和脚本，并保存来源与版本记录。安装后回到 **当前模式组合** 勾选并保存才会启用；安装本身不会改变当前组合。

更新 `main`，在仓库根目录运行 `start-learning-harness.ps1`。Node 最低要求以根
`package.json` 为准。可以直接打开 `/course-builder` 填写并创建课程，也可以从普通 Pi 会话进入。
课程绑定的学生会话不能切换成教师会话；备课项目绑定不能静默更换。

工作区 `/course-builder` 直接列出已有课程，选择课程回到原有 Pi 会话与已保存进度，
不新建空对话。`/course-builder?sessionId=实际会话ID` 直接读取工作区；课程设置、资料连接、
审批与下载不依赖活跃模型。课程标题下的“编辑课程设置”可以修改已保存的字段，保存使用
打开编辑时的 revision，发生冲突会拒绝覆盖。教师浏览器默认信息不会覆盖已有课程字段。

进入具名教师工作区时装入并核验 Course Builder；点击任务前再次确认实际状态。若旧 Skill 快照已过期，显式启动会在同一个
Pi JSONL 中追加当前完整资源的已核验快照，保持 sessionId、原消息与项目绑定。普通恢复仍严格
校验旧快照；Required 资源缺失或新候选验证失败时不得激活。学生会话不能进入教师工作区。

1. 在字段表单中填写教师、课程、周数、课次、时长、学生层次、目标和 Beamer 配置。
   无需预先打开会话；点击创建时才建立具名 Pi 会话并绑定课程，不启动模型。重复提交同一创建请求
   返回原有课程与会话。课程编号中的空格和斜杠按页面预览转为短横线。新课程表单在当前标签页
   自动保存，刷新可恢复；“保存草稿文件 / 载入草稿文件”可跨标签页保留尚未提交的字段。
   教师姓名、机构、语言、比例和字号作为本机浏览器偏好保存，课程身份与内容仍由项目存储负责。
2. 点击“链接本地资料文件夹”，在本机目录选择器中选中课程资料根目录。Host 递归登记文件清单、
   相对路径、大小和修改身份，不复制正文，也不把整个文件夹加入模型上下文。文件扩展名不决定
   文件能否成为资料。需要保留一个独立副本时，也可以使用“上传文件副本”。
3. 需要布置作业时，在“Assignment 独立工作链”填写名称和要求，为该 Assignment 选择专属资料
   文件夹，再启动 Assignment Agent。每个 Assignment 单独保存资料、草案 revision 和教师审批；草案
   会在工作区按学生任务、提交物、评分标准和教师用解题提示展示，并可下载学生版或教师版 Markdown。
4. 点击“分析资料”“生成学期计划”，在同页右侧 Agent 对话查看完整流式输出，或直接与 Agent 讨论修订。
5. 阅读工作区内的实际已保存草案，批准或写意见要求修改。
6. 学期计划批准后生成单课计划；单课批准后生成 Beamer。
7. 编译、检查日志、下载 PDF。人工逐页检查后才点击“接受”。

进入路径由你操作：主页空对话也有“备课 · 继续已有课程”入口；已有会话可点击“打开备课工作区”。
进入工作区后，可用“模式与生效资源”查看本次实际加载的物理 Skill、完整正文 Hash
和 Runtime verified 状态。尚未启动 Agent 时，工作区可编辑不代表模型已激活。

Course Builder 默认加载：课程与 Beamer 规划、学习蓝图、学会学习、课程连续性、证据台账、
最小修订、做中学和教学可视化。Teach-back 作为条件性 Skill 同时可用。Required Skill
文件缺失、变更或正文不完整时，候选 Runtime 不会激活。

模型使用 Pi 设置中的 Provider/Model。没有真实凭据时，不能生成教学文本。
工作区按钮发送任务给当前 Pi，不会自行创建另一个模型循环。可在自定义消息框
提交修订要求；状态会定期刷新。选择旧计划的 revision 会被拒绝。

## 跨课次覆盖 Checkpoint

“模块跳转 → 覆盖进度”中，每节课对每个文件只有一条 Checkpoint，记录本课实际使用内容、可选接续定位、该文件下次从哪里继续；不按读取批次拆成多个范围。已存的范围记录按文件汇总展示，原始修订历史保留。一个文件不能在同一课的新记录中重复出现。

可以手工填写，也可以点击“让 Agent 整理本课 Checkpoint”，让它读取现有教案、课件与原始资料后补记；该任务不重做教案或课件。已有课程初始显示“未记录”，不会自动杜撰历史覆盖范围。Agent 与手工保存均先产生“计划覆盖”记录，教师核对后点击“确认当前覆盖记录”。这表示备课范围已确认，不是已经上课或学生已掌握。

后续“生成所选课次计划 / Beamer”会带入此前 Checkpoint，并要求先通过 `read_checkpoints` 读取覆盖范围，说明哪些只是简短复习、哪些是新增内容。超出内联预算时明确要求分页读取，不静默截断记录。新的教案或课件保存后通过 `save_checkpoint` 更新衔接记录，模型不能自行确认。

Checkpoint 单独保存修订历史；切换课程内对话、刷新或重启后仍可读取。修改参考资料并重新索引、修改教案、课件或学期规划后，旧记录显示“待核对”，不能继续确认为当前覆盖。修改 Checkpoint 本身不会改变教案/课件版本或批准状态。编辑期间其他对话保存了更新版本时，旧表单会提示冲突并保留填写内容。

测试：`node --test scripts/course-coverage-checkpoints.test.mjs` 检查真实 SQLite 持久化、作用域、修订与来源；`node apps/pi-web/scripts/course-workspace-navigation-smoke.mjs` 检查表单、确认、刷新恢复和并发冲突。

## 编译只用于可信本地源码

默认关闭 TeX 执行。明确认可源码后，在启动服务前设置：

```powershell
$env:PI_COURSE_BUILDER_TRUSTED_TEX = "1"
# 仅当 xelatex 不在 PATH 中时设置：
$env:PI_XELATEX_PATH = "C:\path\to\xelatex.exe"
.\start-learning-harness.ps1
```

`-no-shell-escape`、受限路径、输入/输出预算、临时目录、环境过滤和超时并不等于
操作系统沙箱。不要编译故意恶意的第三方 TeX。环境变量只能由本地所有者设置，
备课模式默认只启用专用工作流工具；本地用户可以从对话工具菜单开启 read、shell、write/edit 等普通 Pi 工具。PowerShell/Bash 使用本机设置，可修改并重新加载；开启普通工具后不再具有“Agent 无任意文件/命令访问”的边界。教师批准仍由教师 UI 执行。命令缺失会显示失败，不伪造 PDF。

源码必须是独立 Beamer 文档，不支持任意 `input/include` 和外部 BibTeX。
使用 `thebibliography`。导入模板作为资料，由 Agent 合并为独立源码。
图片通过 `assets/材料ID.png`（对应 jpg/jpeg/pdf 扩展名）引用，并列入 `assetMaterialIds`。

## 实际范围

修订默认保留已有资产，只修改用户指出的部分。只有用户明确表示放弃现有资产时才整份重写。Agent 可用 `patch_deck` 对已保存源码做唯一匹配的精确替换，提交当前 deck/lesson 修订；匹配失败或版本冲突时整批不保存。新建课件仍用 `save_deck`，修订后编译并读回验证。

聊天输入框的附件按钮、拖放和文件粘贴支持普通文件与图片。文件以独立副本保存在当前工作目录的 `.pi/chat-attachments`，消息包含可点击原文件/文本链接，正文按需读取，不自动导入课程资料库。课程 Agent 用 `read_attachment`，受当前对话与 Assignment 作用域限制。PDF、PPTX、DOCX 和文本可提取文字；没有适配器的二进制保留原文件并明确说明能力限制。每批 1–10 个文件、总计最多 25 MiB，图片沿用原 Pi 限额。

编译失败会向 Agent 返回 TeX 原始错误（包括没有行号的 `!` 报错）和末尾日志摘录。Agent 可用 `read_compile_log` 按编译回执 ID 分页读取完整持久日志，再通过 `read_deck` 修正源码、保存新版本并重新编译；普通源码错误不应只报告退出码后停下。日志读取保留课程和 Assignment 边界。中途生成的部分 PDF 不代表成功。

- 备课工作区通过“返回 Pi”回到完整主界面，使用原有侧栏顶部“＋ 新建”打开普通对话。原备课工作区继续保存；新对话不继承当前备课模式或消息。模式选择条保留独立的顶部布局空间，不能遮住原有会话控件。
- 在“让 Agent 开始备课”中选择学期计划里的周次、课次和主题，再使用“生成所选课次计划”或“生成所选课次 Beamer”。未满足学期/单课审批时，按钮旁显示具体原因。服务器会重新核对实际课次与版本，Beamer 必须对应所选课次的当前已批准单课计划。

- 本地资料：链接时只建立文件清单；Agent 通过 `read_material` 选择一个材料并分页读取。文件在磁盘上
  被修改、移走或越出已选根目录时读取失败并说明原因，不会静默使用另一份内容。再次选择同一个
  文件夹会原子更新同名文件与新增清单项、提高用于并发保存检查的项目 revision；不会使学期、单课计划或课件审批失效。新题目和参考资料可直接用于后续备课。
- 扩展名只选择按需解析器。PPTX 使用 ZIP/CRC/实际页序与 Speaker Notes；PDF 使用有预算的
  pdftotext；TeX、Markdown、文本和可安全识别的 UTF-8 文件直接读取；图片保留为资产。未知二进制
  仍保留在清单中，读取时明确报告当前没有文本解析器。
- 学期与单课：严格字段、课程容量/目标/材料检查、乐观并发与祖先 revision 绑定。
- 学期规划单独跟踪 `planningRevision`，仅周数、每周课次、课时、教学对象、语言和目标变化会推进它。课程名称、教师署名、课件样式及资料清单不推进它。旧版未记录该字段时保留已有审批，并核对当前课次容量和目标覆盖；不会根据混合用途的旧项目版本号推断大纲已过期。升级后的规划条件修改均会被追踪。
- “额外要求”会随分析资料、生成学期计划、生成所选课次计划/Beamer 的按钮一起发送，并保留供下一次任务使用。直接点“发送给 Agent”只发送该输入内容，成功后清空；失败保留输入。
- Assignment：`assignment_state` 只返回一个作业及其专属资料；`read_assignment_material` 必须携带
  相同 Assignment ID；`save_assignment` 只接受该资料清单中的 ID。课程 `state`/`read_material` 不暴露
  Assignment 资料。教师点击“启动 Assignment Agent”时，Host 还会把这次 Agent 运行固定到所选作业；
  即使同一对话曾出现另一个 Assignment ID，也不能切换或交叉读取。作业资料、草案和审批只更新该
  作业的 revision，不改变课程项目 revision，因此不会使学期与单课计划过期。启动普通课程任务会
  显式回到课程作用域。
- 审批：教师 UI 的单独动作；模型工具表中不存在 approve/accept。
- 课件：独立 .tex、实际编译回执、PDF/日志哈希、当前证据接受与恢复。
- 源码审查：固定规则和日志诊断；不是语义正确性证明，也不是截图视觉检查。
- 可视化：`visual_templates` 返回五种固定 Renderer 的精确 Schema 与样例，`visual` 生成并验证独立 HTML；工作区可打开预览。当前不自动转图片插入指定 Frame。
- 保存：同一 SQLite/WAL 所有者；上传副本、PDF 和日志持久化，本地链接只持久化清单与路径身份，
  并保留修改审计与版本检查。

本版本是单用户本地教师工作区，不是多租户学校服务；请求 Origin 检查和教师 UI
header 不是独立用户身份系统。普通 Coding Mode 本身有本机权限，不应赋予不可信用户。

## 自动测试与未完成事项

本地完整提交前检查（不会推送、触发 Actions 或合并）：

```sh
bash scripts/verify-course-builder-local.sh
```

该检查先拒绝缺入口/接线文件、不兼容 Node 和未安装的锁定依赖，再运行真实
XeLaTeX 回归、根仓库构建/检查/隔离测试，以及 Pi Web 类型检查、lint、测试和构建。
任何一步失败即退出；专项回归通过不能代替整个检查通过。

专项调试：

```sh
PI_TEST_XELATEX=1 node --experimental-strip-types --test scripts/course-builder*.test.mjs
npm run check
npm test --prefix apps/pi-web
npm run build --prefix apps/pi-web
```

回归测试先在旧失败树运行并失败，再修复入口/实际接线。真实 XeLaTeX 测试要求
编译器存在；不把跳过测试或仅存在源码当成通过。远端 CI 结论以该 PR exact HEAD 为准。
